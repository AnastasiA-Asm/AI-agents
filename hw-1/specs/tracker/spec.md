# Спецификация трекера

## ADDED Requirements

### Requirement: Автономное приложение

Приложение MUST поставляться одним файлом tracker-v2.html со встроенными CSS и JavaScript и MUST работать без CDN, внешних библиотек, внешних ресурсов и API-ключей.

#### Scenario: Открытие без сети
- **WHEN** пользователь открывает tracker-v2.html в обычном браузере без подключения к сети
- **THEN** обязательные функции трекера доступны.

### Requirement: Данные и стартовый пример

Каждая задача MUST содержать id, title, hours и done. Идентификатор MUST однозначно определять задачу.

При начальной инициализации приложение MUST показывать:
- «Чтение»: 2 ч, done=true;
- «Практика»: 4 ч, done=false;
- «Повторение»: 2 ч, done=false.

#### Scenario: Начальное состояние
- **WHEN** приложение инициализировано стартовым примером
- **THEN** всего отображается 8 ч, выполнено 2 ч, прогресс составляет 25%.

### Requirement: Изменение задач

Добавление, удаление и переключение done MUST изменять данные задач. Список и показатели MUST отражать актуальные данные.

Новая задача MUST создаваться с done=false.

#### Scenario: Добавление задачи
- **WHEN** пользователь добавляет задачу с допустимыми названием и часами
- **THEN** новая задача появляется в данных с собственным id и done=false, а показатели пересчитываются.

#### Scenario: Удаление задачи
- **WHEN** пользователь удаляет задачу
- **THEN** эта задача удаляется из данных и больше не участвует в расчётах.

#### Scenario: Переключение выполнения
- **WHEN** пользователь переключает отметку выполнения задачи
- **THEN** done меняется на противоположное значение, список и показатели обновляются.

### Requirement: Проверка формы

Название после trim MUST быть непустым.

Часы MUST быть конечным числом от 0,5 до 24 включительно с шагом 0,5. Пустое значение MUST считаться ошибкой и MUST NOT трактоваться как ноль.

При ошибке приложение MUST:
- не добавлять задачу;
- показывать ошибку рядом с соответствующим полем;
- сохранять введённые значения формы.

#### Scenario: Пустое название
- **WHEN** пользователь отправляет форму с пустым названием или названием только из пробелов
- **THEN** задача не добавляется, рядом с названием видна ошибка, введённые значения сохраняются.

#### Scenario: Пустые или отрицательные часы
- **WHEN** пользователь отправляет форму с пустыми или отрицательными часами
- **THEN** задача не добавляется, рядом с часами видна ошибка, введённые значения сохраняются.

#### Scenario: Нарушение диапазона или шага
- **WHEN** часы не являются числом, выходят за диапазон 0,5–24 или не кратны 0,5
- **THEN** задача не добавляется и рядом с часами видна ошибка.

#### Scenario: Допустимые значения
- **WHEN** название после trim непустое, а часы соответствуют диапазону и шагу
- **THEN** задача добавляется с обрезанным по краям названием и числовым значением hours.

### Requirement: Общие показатели

Приложение MUST рассчитывать:
- итоговые часы как сумму hours всех задач;
- выполненные часы как сумму hours задач с done=true;
- прогресс как округление до ближайшего целого числа значения 100 × выполненные часы / итоговые часы.

При отсутствии задач итоговые и выполненные часы MUST равняться 0, прогресс MUST равняться 0%. Значения NaN и Infinity MUST NOT отображаться.

#### Scenario: Выполнение «Практики»
- **GIVEN** загружен стартовый пример
- **WHEN** «Практика» отмечена готовой
- **THEN** выполнено 6 из 8 ч, прогресс составляет 75%.

#### Scenario: Удаление всех задач
- **WHEN** все задачи удалены
- **THEN** список пуст, итоговые и выполненные часы равны 0 ч, прогресс составляет 0%.

### Requirement: Фильтрация списка

Фильтр MUST поддерживать режимы «все», «активные» и «готовые».

Фильтр MUST влиять только на видимый список. Итоговые часы, выполненные часы и прогресс MUST рассчитываться по всем задачам независимо от фильтра.

#### Scenario: Фильтр «активные»
- **GIVEN** загружен стартовый пример
- **WHEN** включён фильтр «активные»
- **THEN** видны только «Практика» и «Повторение», всего остаётся 8 ч, выполнено 2 ч, прогресс остаётся 25%.

#### Scenario: Фильтр «готовые»
- **GIVEN** загружен стартовый пример
- **WHEN** включён фильтр «готовые»
- **THEN** видна только задача «Чтение», общие показатели не меняются.

### Requirement: Читаемый интерфейс

Интерфейс MUST оставаться читаемым на ширине 390 px без горизонтального скролла. Поля и кнопки MUST иметь понятные подписи.

#### Scenario: Узкий экран
- **WHEN** ширина области просмотра составляет 390 px
- **THEN** список, форма, ошибки, фильтры и показатели читаемы, элементы управления доступны, горизонтального скролла нет.

### Requirement: Необязательное сохранение

Эта возможность не обязательна для базовой реализации.

Если сохранение реализовано, приложение MUST сохранять задачи в localStorage и восстанавливать их при следующем открытии, когда хранилище доступно.

При недоступном хранилище приложение MUST показывать понятное сообщение и MUST продолжать работу в памяти.

#### Scenario: Восстановление сохранённых задач
- **GIVEN** необязательное сохранение реализовано и хранилище доступно
- **WHEN** пользователь повторно открывает приложение после изменения задач
- **THEN** восстанавливается сохранённый список, включая сохранённый пустой список.

#### Scenario: Недоступное хранилище
- **GIVEN** необязательное сохранение реализовано
- **WHEN** чтение или запись localStorage недоступны
- **THEN** пользователь видит сообщение об отсутствии сохранения, а добавление, удаление, переключение выполнения и расчёты продолжают работать в памяти.
