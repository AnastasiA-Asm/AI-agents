# ДЗ №1: мини-трекер учебных задач

Асманова Анастасия. Вариант А.

Я сравнила два способа разработки мини-трекера на одной модели GPT-6.1 Sol:

- `tracker-v1.html`: прямой короткий запрос сразу на реализацию.
- `tracker-v2.html`: сначала спецификация в формате OpenSpec, без CLI, затем реализация отдельным запросом.

OpenSpec CLI не запускался. Обе версии являются автономными HTML-файлами со встроенными CSS и JavaScript.

## Запуск

1. Скачайте файлы репозитория или архив с ними и распакуйте.
2. Откройте `tracker-v1.html` или `tracker-v2.html` обычным браузером.
3. Установка библиотек, сервер, сборка и API-ключи не нужны.

Обе версии я проверяла вручную в Яндекс Браузере на Windows. Ширину 390 px проверяла через инструменты разработчика.

## Файлы

| Путь | Содержание |
| --- | --- |
| `tracker-v1.html` | Первая реализация |
| `tracker-v2.html` | Вторая реализация |
| `proposal.md` | Цель и границы второй попытки |
| `specs/tracker/spec.md` | Требования MUST и сценарии WHEN/THEN |
| `design.md` | Модель данных и расчёты |
| `tasks.md` | План реализации и проверок, полученный до написания кода |
| `prompts.txt` | Модель, даты, время начала, время ответов по интерфейсу и все три экспериментальных запроса |
| [REPORT.md](REPORT.md) | Фактические результаты, затраты, различия и ограничения |
| `screenshots/` | Снимки экранов для подтверждения проверок |

В `tasks.md` сохранён первоначальный план с незаполненными отметками. Итоговое состояние проверок описано в `REPORT.md`.

## Исходные данные и проверки

| Задача | Часы | Выполнена |
| --- | ---: | --- |
| Чтение | 2 | Да |
| Практика | 4 | Нет |
| Повторение | 2 | Нет |

Общая приёмка: T1 — исходный пример; T2 — выполнение «Практики»; T3 — фильтры; T4 — валидация; T5 — удаление всех задач и дальнейшая работа.

По полной постановке исходные показатели равны 8 ч, 2 ч и 25%; после выполнения «Практики» — 8 ч, 6 ч и 75%. В исходной v1 процент считается по количеству задач и составляет 33%/67%. Это зафиксированное различие первой попытки; её код сохранён без исправлений.

Обе версии могут восстанавливать ранее сохранённые задачи вместо исходного примера. Для независимого сценария вручную восстановите пример: выберите «Все», удалите текущие задачи, добавьте три задачи из таблицы и отметьте выполненным только «Чтение».

Сохранение в localStorage — дополнительная функция. При открытии через `file://` поведение зависит от браузера. В версиях подтверждено сохранение задачи после обновления страницы в браузере, где проводилась проверка.
